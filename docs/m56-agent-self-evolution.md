# M56：让 Agent 自己进化策略（不只是改检索词）

## 之前的问题

RSI 的白名单里有 `plan_prompt`，但 `propose()` **只会生成 synonyms**——
所以"自我进化"实际只改过检索词，Agent 的行为从没变过。

## 现在的闭环

```
1. 用当前策略在 dev(8 条) 上跑真实 Agent → 收集失败/高开销用例
2. 把轨迹（问题、调了哪些工具、步数、答案片段、失败项）交给模型
3. 模型写一段 ≤200 字的"策略补丁"（plan_prompt），进入 system prompt
4. 候选在 dev 重跑；通过率提升 或 工具调用下降 ≥20% 才有资格
5. held-out(6 条) 不退步才晋级；写快照 + rsi_log；可 rollback
```

关键设计：**允许"效率型晋级"**。通过率已经 100% 时，只盯通过率会让进化停滞；
真实产品里"同样答对、少调 33% 工具"就是改进。

## 实测（DeepSeek V4.1 Flash）

**第一轮：候选被拒（这是好现象）**

```
基线 dev 75% / held 100%
候选 ×2：dev 75% → 75%
→ rejected：dev 没有提升
```

（顺带发现评测器漏了 setup：记忆类用例根本没写记忆，已修。）

**第二轮：效率型晋级**

```
基线  ：pass 100% | 平均工具调用 4.12 | $0.0154 | 67s
进化后：pass 100% | 平均工具调用 2.75 | $0.0154 | 53s   ← −33% 调用、−21% 耗时
策略："同一工具、同一参数只调一次，绝不重复；find_expert 整轮最多 1 次；…"
结果：promoted（dev 100% / held 100%，效率型晋级）
```

## 为什么这个结果可信

1. **闸门先拒绝过一次**：说明它不是"为了展示而放行"；
2. **held-out 独立**：策略在 dev 上产生，held-out 上没有退步；
3. **指标是外部测的**：工具调用次数来自 agent 的 `steps`，不是模型自评；
4. 可回滚：`rsi.rollback(gen)` 一条命令。

## 局限

1. dev 只有 8 条、held-out 6 条，统计置信度有限；
2. 策略以"减少重复调用"为主，还没有进化出**路由级**规则（例如"人名问题先 profile"）；
3. 每代约 4 分钟、$0.03–0.06；跑 10 代需要约 $0.5；
4. 没有对"策略漂移"做长期监控（连续多代晋级后是否变差）。
