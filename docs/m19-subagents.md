# M19：三个子 Agent（researcher / analyst / verifier）

## 为什么要拆角色

一个"全能 Agent"会把检索结果、指标计算、事实核对全塞进同一个上下文：
贵、慢、而且容易自相矛盾（自己找的候选人自己打分，天然偏袒）。

拆开之后每个角色只做一件事：

| 子 Agent | 只负责 | 不做 |
|---|---|---|
| researcher | 多通道召回候选 + 给证据指针 | 不解释、不打分 |
| analyst | 读档案算指标（h-index/主题/节奏） | 不检索（避免被召回结果带偏） |
| verifier | 逐条核对结论能否回溯 | 不生成新结论 |

每个角色的产出都写成结构化 JSON 落到 VFS（`/agents/{role}/{tid}.json`），
主上下文只拿一行摘要 + 路径。

## 实测：上下文压缩 29 倍

一次"审稿人匹配"任务（6 步）：

| 步骤 | 摘要 | 落盘产物 | 耗时 |
|---|---|---|---|
| 抽取稿件主题 | 60 B | — | 34 ms |
| researcher 召回候选 | 36 B | 1,963 B | 143 ms |
| analyst 算指标 | 31 B | 2,503 B | 60 ms |
| 打分与利益冲突 | 61 B | — | 41 ms |
| verifier 证据校验 | 40 B | 1,466 B | 57 ms |
| 生成报告 | 26 B | 1,491 B | 33 ms |

**主上下文合计 254 B；落盘产物 7,423 B；压缩比 29.2×**

这就是简历里"上下文管理、减少 Token 消耗"的可测版本——不是口号，是 29 倍。

## 一个真实的失败被 verifier 抓住

问题：**谁更适合审一篇关于肺癌免疫治疗的稿件**

researcher 召回 4 人，analyst 算完指标，打分把
**Hanzhang Chen**（h=24，108 篇）排到第 2。

但 verifier 发现他的近五年标题高频词是：

```
crystal(9)、structure(8)、optical(7)、crystals(5)、ccdc(5)
```

——是**晶体结构**方向，和"肺癌免疫治疗"毫无关系。同名不同人。

verifier 驳回后，报告把他从榜单剔除：

```
| 1 | Ying Cheng（第二军医大学） | h=85 | 888 篇 | 主题命中 3 | 0.656 |
| 2 | Xin Xu（嘉兴大学）        | h=19 | 82 篇  | 主题命中 2 | 0.435 |

被 verifier 驳回（领域不符，不计入榜单）：Hanzhang Chen（2 词）、Guilin Peng（2 词）
证据校验：提交 12 条，通过 10 条，通过率 83%
```

**如果没有 verifier，这个"同名不同人"会直接进推荐名单**——这正是可解释 Agent
比"大模型直接答"更可靠的地方。

## 中英主题映射（必须做的一步）

中文问题"肺癌免疫治疗"直接去搜英文语料几乎不命中。加了一张医学主题词表：

```python
"肺癌":   ["lung cancer", "nsclc"]
"免疫治疗": ["immunotherapy", "immune checkpoint", "pd-1", "pd-l1"]
"慢阻肺":  ["copd", "chronic obstructive"]
"肠道菌群": ["gut microbiota", "microbiome"]
```

**第一版没做映射时**，关键词抽成了"审一篇关 / 于肺癌免 / 疫治疗 / 稿件"，
researcher 召回 0 人，整条链路直接崩。

## 打分规则（写在报告里，可复核）

```
得分 = 0.5 × 主题命中率 + 0.3 × min(1, log10(1+h)/2) + 0.2 × 近五年产出占比
```

- 主题命中：稿件主题词（拆成单词）出现在候选人近五年标题词频里的数量
- 明确**不是**"学术水平"评价，只是"领域匹配 + 活跃度"的粗排

## 遗留问题

1. **候选池只有 102 人（有深档案的）**，所以"审稿人匹配"实际是在 102 人里挑；
   全库 8,490 人里大部分没有完整成果，无法算 h-index 与主题分布。
2. **Guilin Peng 被误杀**：他做肺移植（lung/transplantation），
   和"肺癌免疫治疗"确实不完全对口，但对"肺癌外科"稿件就是合适的审稿人。
   当前主题词表太粗，需要更细的领域标签（子领域级）。
3. **verifier 只校验"能不能回溯"，不校验"结论是否合理"**：
   它能发现同名不同人，但发现不了"h-index 高就一定适合审稿"这种逻辑问题。
