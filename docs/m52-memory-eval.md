# M52：记忆评测（五能力 × 10 条）

## 设计

记忆评测最容易犯的错是"只测记住，不测忘记"。所以按 LongMemEval 的五能力拆开：

| 能力 | 考什么 | 反例（会判失败） |
|---|---|---|
| `extraction` | 说一句自述能否落库 | 把"找研究 dementia 的专家"抽成用户偏好 |
| `multi_session` | 上一轮说过的，下一轮还用得上 | 只在当前会话内记 |
| `temporal` | as-of 查询区分"以前/现在" | 旧值被覆盖删掉 |
| `update` | 转向后旧方向必须失效 | 同时推荐 AD 与帕金森 |
| `abstain` | 记忆里没有的，不能编 | 无记忆也加"已按你的长期记忆" |

判定全部机械可判：`fact_any` / `fact_none`（防过期复用）/ `note`（是否带记忆说明）/ `refused`。

## 结果（50 条）

```
通过率        100%（50/50）
过期事实误用  0%
记忆进检索    76%（40 条有记忆用例中 95%；10 条 abstain 本不该有记忆）
p95          4073ms
```

逐能力都是 100%。

## "记忆进检索 76%" 这个数最重要

如果只报"通过率 100%"，会掩盖一个事实：**记忆可能只是加了一句说明，没真正改变检索**。
所以额外统计 `memory_fills`（来自 `tool_find_expert` 的 `memory.fills`）：

- 10 条 abstain 天然为 0；
- 40 条有记忆的用例里，38 条真正把记忆补进了 facet 条件；
- 剩下 2 条的主题既不在 `topic_en` 词表也不在兜底表里——这是**词表覆盖**问题，不是记忆问题。

这个指标逼出了 4 个 bug（详见 [m51](m51-user-memory.md)），其中两个是"记忆根本没进链路"。

## 评测集维护

- 用例在 `eval/memory.jsonl`，每条自带 `setup_queries`（走真实抽取，不直接写库）；
- 每个用例用独立 `uid`（`eval-<id>`），跑前 `clear`，互不污染；
- `temporal` 用例用 `setup_facts` 指定时间，避免"今天写、今天查"测不出时间语义。

## 局限

1. 50 条仍偏少，句式集中在中文自述；
2. `note` 判定是子串匹配（"（已按你的长期记忆"），措辞变了会误判；
3. 没有测"记忆冲突"（同时有效的两个方向）；
4. 情景记忆（`mem_event`）只记录，尚未参与排序，所以没有对应指标。
