# M30：Facet 检索（像 AMiner 助手那样理解"条件"）

## 问题

之前的"找专家"只有一条路：把整句话丢进论文检索，再用交叉编码器打分。
但用户真实的问题往往带**硬条件**：

```
中国的呼吸科专家，被引超过 1000，前 5
美国做机器学习的大学教授
清华的高被引学者
```

"中国""大学""被引≥1000"是**过滤条件**，不是语义相似度能表达的东西。
把整句话做向量检索，等于让模型去猜"中国"该怎么相似。

## 做法：自然语言 → 结构化条件

`app/facets.py` 把查询拆成：

| 维度 | 示例输入 | 解析结果 |
|---|---|---|
| 主题 | 呼吸科 / 机器学习 / AI | `respiratory`（中英词表映射） |
| 国家 | 中国 / 美国 / 英国 | `CN` / `US` / `GB` |
| 机构类型 | 大学 / 医院 / 研究所 / 企业 | `university` / `hospital` / `institute` / `company` |
| 机构名 | 清华 / 协和 / 哈佛 | `Tsinghua` / `Peking Union Medical` / `Harvard` |
| 被引下限 | 高被引 / 被引超过 5000 | `1000` / `5000` |
| 排序 | 引用最多 / 论文最多 / 最近活跃 | `cites` / `works` / `recent` |
| 条数 | 前 5 / top 10 | `5` / `10` |

然后走"过滤 + 排序"的 SQL，而不是向量检索。

## 三个关键工程决策

**1. 主题必须翻译成英文**
语料是英文，"机器学习"直接进 FTS 命中 0。用词表映射成 `machine learning`；
同义词之间用 **OR** 而不是 AND——`respiratory` 和 `pulmonary` 同时出现在一个人身上的
概率很低，用 AND 会把"中国的呼吸科专家"查成 0 人（踩过）。

**2. 条件短语必须从主题里剥干净**
第一版没剥，主题变成 `呼吸科 ，被引超过 1000，前 5`，FTS 必然 0 结果。
现在按"命中的短语逐个删除"再抽主题。

**3. 条件过严要自己放宽并说明**
"中国 + 呼吸 + 被引≥1000"一开始只有 13 人（且国家数据当时没补全）。
现在 0 结果时会自动放宽被引门槛，并在回答里写清
「没有同时满足『被引≥1000』的人，已自动放宽该条件」——不静默降低标准。

## 顺带补的数据：国家

`people.country` 一直是空的（采集时没存）。新增 `app/enrich_country.py`：
从 OpenAlex 作者记录的 `last_known_institutions[].country_code` 批量回填（50 人/次）。

实测补全率 **95%**（200 人试跑补上 190），后台按被引从高到低补，
覆盖：US 1,555 / GB 370 / CN 348 / FR 153 / CA 137 …

## 效果

| 查询 | 解析出的条件 | 结果 |
|---|---|---|
| 中国的呼吸科专家，被引超过 1000，前 5 | 主题=呼吸、国家=CN、被引≥1000 | 10 人（Bo Yang / Roujian Lu / Guizhen Wu…） |
| 美国做机器学习的大学教授 | 主题=机器学习、国家=US、类型=university | 5 人（Tibshirani / Hastie / Friedman） |
| 清华的高被引学者 | 机构=Tsinghua、被引≥1000 | 6 人（Gao Ming Huang / 戴琼海…） |
| 企业里的 AI 专家 | 类型=company、主题=AI | 11 人（但见下方数据噪声） |

回答会**先回显条件再给结果**：

```
我把它理解成了结构化条件：**主题=呼吸、国家=CN、被引下限=1000、排序=cites、limit=5**。
命中 **10** 人：
1. **Bo Yang** — CN · Capital Medical University；被引 49,162（样本内 3 篇）
...
> 识别依据：国家=CN；被引≥1000；主题≈呼吸
```

这样用户看到"理解错了"可以直接改说法，而不是拿到一堆莫名其妙的结果。

## 接口

```
GET /experts/facets     # 可选的国家 / 机构类型及人数（给前端做筛选条）
```

返回示例：`countries: US 1555, GB 370, CN 348 …`；
`inst_kinds: university 4354, hospital 1252, institute 1009, company 11`。

## 两个诚实的数据问题

1. **`company` 只有 11 人，且混进了期刊名**：
   OpenAlex 的 `last_known_institutions` 有时填的是出版方（如 `Neurology, Inc`），
   被我们的机构类型规则判成"企业"，所以"企业 AI 专家"里会出现神经科医生。
2. **`works_count` 是"样本内"篇数**，不是全部论文数。
   回答里已改成 `被引 49,162（样本内 3 篇）`，避免"3 篇被引 4.9 万"的误读。

## 遗留

1. **facet 只接了 `find_expert`**：`/experts` 接口还没支持同样参数，前端筛选条也没做；
2. **国家覆盖率还在补**（后台任务），医学之外的国家数据可能偏少；
3. **没有"多轮收窄"**：AMiner 那种"先给 20 人，再按机构/年份二次筛选"还没做。
