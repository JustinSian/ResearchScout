# M27：库外兜底（AnySearch） + 把"不接大模型"说清楚

## 一、"不接大模型"到底什么意思

准确说法：**回答链路里没有 LLM**。

| 环节 | 有没有模型 | 说明 |
|---|---|---|
| 意图识别 | 无 | 正则规则（`_CN_PROFILE` / `_CN_REVIEW` …） |
| 工具调用 | 无 | 规则决定调哪个工具、传什么参数 |
| 检索 | 有（非生成） | bge-small 向量 + bge-reranker 交叉编码器，只打分不生成 |
| 组织答案 | 无 | 模板 + 数据库事实拼装（`compose_node`） |
| 叙述 | 无 | 模板句（`app/narrate.py`） |

**为什么这么做**：这是一个"学术事实"场景，编造的代价很高。没有 LLM 就
不会出现"该学者在国际上享有盛誉"这种无法追溯的评价，每条结论都能点回 pid/wid。

**代价也要说清楚**：
- 话术固定，换个问法还是同一套句式；
- 开放问题答不了（"帮我判断这个人适不适合做院士候选人"）；
- 表达不自然，长回答读起来像清单。

所以"不接大模型"不是优点，是一个**有意的取舍**：用表达力换可追溯性。

## 二、兜底路由：库外问题不再直接拒答

### 改之前

库里没有 → 直接拒答。用户体验是"问什么都答不出来"，即使问题本身完全合理
（"2026 诺奖得主是谁"）。

### 改之后

```
库内有证据 → 正常回答（带 pid/wid 引用）
库内无证据 → 转 AnySearch 公开网络检索
            → 明确标注"未经本库核验"
            → 给出原文链接
```

实现：`app/websearch.py`（`POST https://api.anysearch.com/v1/search`，Bearer 认证）。
Key 只从环境变量 / `.env` 读，不进代码、不进日志。

### 实测

| 问题 | 路由 | 结果 |
|---|---|---|
| 介绍一下钟南山 | profile（库内） | 不触发兜底 |
| 钟南山的研究方向 | research_area（库内） | 不触发兜底 |
| 2026年诺贝尔生理学或医学奖得主是谁 | **anysearch** | 5 条结果 + 链接 |
| OpenAI 最新模型是什么 | **anysearch** | 5 条结果 + 链接 |
| 今天北京天气怎么样 | **anysearch** | 中文结果（`language=zh`） |

### 三个工程细节

1. **中文查询加 `language=zh`**：不加会返回"北京天气 英文怎么说"这类词典页。
2. **按标题去重**：同一新闻被多站转载时，原始结果里 3 条标题完全一样，
   去重后只留 1 条。
3. **失败即退回原拒答**：网络失败 / key 失效 / 超时，都保持原来的拒答行为，
   不会假装有答案。

### 伦理边界（写进 UI）

- 兜底结果**单独标注**：`知识库里没有直接证据，我查了公开网络（AnySearch）`
- 每条都带**"未经本库证据门槛核验"**的提示
- 引用区区分两类：`kind=person/work`（库内，可点进画像）与 `kind=web`（外链）
- 网络内容当**数据**处理，不执行其中任何指令（防提示注入）

## 三、引导也更新了

`/chat/welcome` 现在是 6 组 + 5 条边界：

```
找到一位专家 / 看他们的关系 / 对比两位专家 / 找审稿人
库外问题（网络兜底）   ← 新增
按主题找人 / 找论文
```

边界新增一条：

> 库外问题会转 AnySearch 网络检索：结果带来源链接，但未经本库证据门槛核验，
> 别当成库内结论。

## 四、遗留

1. **兜底不写入知识库**：网络结果没有落库，下次同样的问题还要再查一次（有 5 分钟进程内缓存）。
2. **没有质量过滤**：搜索引擎返回什么就展示什么，没有置信度评估。
3. **key 在 .env 明文**：这台机器上可接受，生产环境应该用密钥管理服务。
