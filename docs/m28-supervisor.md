# M28：Supervisor 多 Agent 调度（做与不做的边界）

## 一、先回答"现在有没有 Multi-Agent"

**没有。** 之前只有两种东西：

```
/chat  → 单轮规则规划器 → 1 个工具 → 模板拼答案
/task  → harness 规划器 → 6 步 → researcher / analyst / verifier
```

`researcher / analyst / verifier` 是**同进程的三个函数**，共享数据库与上下文，
没有消息传递、没有独立循环、没有协商。准确叫法是「角色分离的流水线」。

## 二、路由审计暴露的问题

19 题实测，旧版**错 8 题**：

| 问题 | 期望 | 旧版 | 后果 |
|---|---|---|---|
| 今天北京天气 | web | find_expert | 靠事后兜底救回 |
| OpenAI 最新模型 | web | find_expert | 同上 |
| 2026 诺奖得主 | web | profile | 同上 |
| **钟南山最近有什么新闻** | hybrid | find_expert | **救不回来**（只答了库内画像） |
| **何建行 2026 年发表了什么** | hybrid | find_expert | 同上 |

## 三、做了什么：Supervisor + 3 Agent + 仲裁

```
query → probe(能力探测) → decide(路由) → 执行 1~2 个 agent → arbiter(合并)
```

| Agent | 职责 | 实现 |
|---|---|---|
| `kb_agent` | 库内工具 + 模板（关闭内部兜底，否则仲裁看不到"纯库内结果"） | `agent.answer(allow_fallback=False)` |
| `task_agent` | 多步尽调（researcher/analyst/verifier） | `harness.run` |
| `web_agent` | 公开网络检索（标注未核验） | `websearch.answer` |

**路由规则**（确定性，无 LLM）：

1. 审稿意图 → task
2. 两人名 + 比较 → task（出对照报告比单轮更全）
3. 人名解析成功 + 要"最新/新闻" → **hybrid**（库内学术侧 + 网络动态）
4. 人名解析成功 → kb
5. 要"最新"但没有具体人 → web（静态语料答不了）
6. 明显库外（天气/股价/赛事）→ web
7. 其余 → kb，答不出自动转 web

**仲裁原则**：

- 库内能答就答，网络只作补充，**永远分节标注**，不混成一段；
- 库内拒答而网络有结果 → 只给网络，并说明为什么没走库；
- 两边都没有 → 明确拒答，不编。

## 四、实测

### 路由准确率

| 集合 | 旧版 | 新版 |
|---|---|---|
| 调参集（19 题） | 11/19 = 58% | **19/19 = 100%**（过拟合，不作数） |
| **留出集（10 题，未参与调参）** | 4/10 = 40% | **9/10 = 90%** |

留出集那 1 个错的值得记：**"钟南山和何建行一起发过哪些论文"** 期望 kb，
实际被判成 hybrid（因为"一起"没有触发混合，"发过哪些论文"也没有 recency）。
影响不大（会多查一次网络），但说明关键词规则的天花板。

### 端到端四种路由

| 输入 | route | 结果 |
|---|---|---|
| 介绍一下钟南山 | kb | 画像 + 4 条引用 |
| 钟南山最近有什么新闻 | **hybrid** | 库内画像 + 网络动态，**9 条引用**，分两节 |
| 今天北京天气 | web | 5 条网络结果 + 链接 |
| 谁更适合审一篇关于肺癌免疫治疗的稿件 | task | 多步报告 |

### 一个降级处理

`task` 路由对不在 102 人档案范围内的主题会失败（"糖尿病肾病"）——
原先直接抛 `RuntimeError`，现在是**降级**：task 失败 → kb → web，
用户看到的是网络结果加一句说明，而不是报错。

## 五、为什么不做"LLM 自主 Agent"

| 形态 | 判断 |
|---|---|
| Supervisor + 3 专用 Agent + 仲裁 | **该做**：修掉 8 个错路由和 2 个混合问题，可测 |
| planner-worker-critic 自由对话、反复自我反思 | **不该做**：没有 LLM 就没有自主性；多一层转发和延迟，指标不会变好 |

**结论写在代码注释里**：这个系统的瓶颈是"覆盖"（102 份深档案、8,490 位发布专家），
不是"智能"。加自主性解决不了覆盖问题，只会让失败更难定位。

## 六、遗留

1. **留出集只有 10 题**，90% 的置信区间很宽（大约 60%~98%）；需要扩到 50 题以上。
2. **路由规则是关键词表**，换个说法就可能失效（"一起发过哪些论文"就漏了）。
3. **hybrid 的子问句是硬拼**（`介绍一下{name}`），对多个人名只取第一个。
4. **task 失败降级后不告诉用户"为什么没走多步"**，只给了网络结果。
