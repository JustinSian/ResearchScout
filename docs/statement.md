# ScholarTrust 项目陈述（简历/面试用，可直接引用）

> 所有数字来自 `docs/m1`～`m16` 的报告，可在服务器 `~/scholar-trust` 复现。

## 一句话

在**没有 docker、没有 sudo、没有 GPU** 的一台机器上，用 FastAPI + SQLite(FTS5) + 两个
ONNX 模型，从 0 重建了一个"学术专家知识库 + 可信采集 + Agent 问答"系统：
47,569 位学者、11,104 篇论文、101,414 条合作边，公网可访问，附 16 份实测报告。

## 我做了什么（按能力分组）

### 1. 数据采集与工程取舍

- OpenAlex 无 key 时**按请求计费**（$0.0001/次，1000 次/天，与 per_page 无关），
  逐人采集必然打光预算 → 改成 **works-first**：一页 200 篇论文带出数百位作者，
  8000 篇只花 40 次请求。
- `cursor` 翻页在无 key 时稳定 401（踩了两次）→ 全部改 page 翻页。
- 全文抓取：arXiv 覆盖 100%（322/323），OA PDF 只有 4%——
  高被引论文和付费墙高度重合，这是结构性限制，不是实现问题。

### 2. 可信采集（这个项目的核心差异点）

- 结构化打分器：身份/产出/影响/归属四组权重 + 置信分层 + 复核队列（带留痕）；
- **人工抽检 60 条**后发现反直觉事实：accept/review/reject 三档**全是真人**
  （采集走 authorship，源头就是人）→ 门槛的作用不是"判是不是人"，而是"筛产出"；
- 非人实体 17 条 100% 被挡；单篇作者不进发布集；
- 扩张时新增"网络背书"通道：与已核验专家共同论文 ≥2 篇且本人作品 ≥10 篇；
  抽样 40 条得精度 **77.5% [62.5%, 87.7%]**，并给了可筛选标记与 5% 占比告警。

### 3. 检索与评测（最"反直觉"的部分）

- BM25(FTS5, porter) + bge-small-en 向量 + RRF/DBSF 融合，全参数可切；
- 自建**两套 gold set**（按被引排序 / 随机抽样），报告 R@10 / MRR / nDCG + bootstrap CI；
- **四次识破自己的评测在骗自己**：
  1. 权威性先验看着 +74%，换随机真值后反而变差 → 标签泄漏，弃用；
  2. 摘要级 chunk 融合在按被引真值上 +0.043 显著，随机真值 −0.056 → 弃用；
  3. 全文 chunk 加入后同样只在"按被引真值"上赢 → 只用于证据引用，不用于排序；
  4. "共享作者集合"这个自创质量指标在单作者数据上大量误报 → 改成逐篇对照上游。
- 结论：**融合没有赢过更强的单路，就不启用融合**（这是 Qdrant 调优指南的判据）。

### 4. Agent（LangGraph）

- 5 个工具：找专家（论文优先 + CE 判相关）/ 画像 / 合作网络 / 论文检索 / 对比；
- **拒答用 cross-encoder 判定**：稠密相似度和 BM25 分都分不开"有/无答案"，CE 可以
  （有答案 ≥0.858，无答案 ≤0.425），阈值 0.60；
- 24 题评测：工具选择 95.8%、拒答 100%、引用 100%；
- 中文适配：中文查询词会打断 FTS 的 AND、会稀释 CE 打分（0.999→0.175），
  都定位并修复；专家主题、机构、人名全部中文化（界面 28/28，整体约 60%）。

### 5. 数据质量（这部分最值钱）

- 用户让我"自己看看图谱"，我从中发现**作者被挂到错误的论文上**：
  根因是 SQLite UPSERT 走更新分支时 `lastrowid` 不刷新；
- 全量重建 48,935 条作者关联 / 88,611 条共著边，抽样 12 篇与 OpenAlex 对照 **12/12 一致**；
- 把踩过的坑做成 `/health/trust` 六项检查，上线当天就抓到 **6,567 人不在 FTS 索引里**（搜不到）；
- 定时守护进程每 6 小时跑一次，异常写告警文件。

### 6. 前端与部署

- 单文件 SPA（无构建）：专家墙（排名/色块头像/迷你条形图/筛选）、画像、Canvas 力导向图谱
  （人/机构两层、三种着色、可拖动）、Agent SSE 对话、复核队列；
- 安全：发现并修掉无鉴权写接口（可投毒知识库）→ X-API-Key + fail-closed，文档默认关闭；
- 压测：检索 ~20 rps 饱和（单 worker + SQLite），chat 图查询 146 rps；
- Cloudflare 隧道公网可访问。

## 三个可以讲的"取舍"

1. **为什么不上图数据库**：没有 docker；而且 1~2 跳、路径、机构聚合在 SQLite 上都够用，
   真正的短板是"图上没有分析"，所以补的是 Louvain 社区（3,081 个，模块度 0.983）、
   最短合作链、机构关系网。
2. **为什么 Agent 用规则规划器**：演示环境没有可靠 LLM；五个意图用规则 100% 判准，
   且每一步可解释、可单测。
3. **为什么保留 7.5% 的噪声**：试过两版主题过滤，一版无效、一版误伤 9 个正常学者，
   而噪声有标记可筛选 → 选择"可解释的噪声"而不是"不可靠的干净"。

## 面试会被追问、要提前准备

- **重名合并没做**：OpenAlex 把钟南山拆成两个 author id（我合并了），但系统性消歧没做；
- **评测规模小**：60 条人工抽样、40 条背书抽样，CI 很宽；
- **网络背书的精度只有 77.5%**，且是我一个人按元数据标的；
- **单机单 worker**：~20 rps 是 SQLite 的极限，不是架构上限；
- **语料一变 nDCG 就变**：从 0.2354 降到 0.1687，是 gold set 固定而分母变大的必然结果，
  每次都要重录基线。
