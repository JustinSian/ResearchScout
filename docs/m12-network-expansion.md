# M12：按图谱关系扩张专家库（以钟南山为种子）

## 目标

不是"再导一个名单"，而是**用图谱当数据源**：以一位已核验专家为种子，
把他全部论文里的合作者拉进来，补档案、过门槛，让他们出现在专家墙上。

## 做了什么

### 1. 拉全量论文

```
filter=authorships.author.id:A5101475024   （钟南山的 OpenAlex author id）
938 篇，6 页 × 200 条
```

**踩坑**：第一版用 `cursor=*` 翻页，第 2 页就 401——这个坑在 M1 就踩过一次
（无 API key 时 cursor 翻页会 401，page 翻页正常）。改成 `page=1..N` 后 6 页全部成功。

### 2. 建边：星形，不是全对全

他的论文里有 100+ 作者的大协作论文，全对全是 4,950 条边/篇。
改成"中心 ↔ 每位合作者"，权重 = 共同论文数：

```
合作者 4,875 人，新建边 2,657 条
```

### 3. 补档案 + 判定

对 4,885 位合作者批量取 OpenAlex author 档案（50 个/次，共 98 次请求），
更新作品数/被引/机构/ORCID/主题，然后跑可信判定，新增一条证据：

| 证据 | 条件 | 分值 |
|---|---|---|
| `coauthor_of_verified` | 与已核验专家**共同论文 ≥2 篇** 且本人作品 ≥10 篇 | +0.25 |

**第一版只要求"有共同论文"**，结果一篇百人论文就能把人抬进发布集（1,919 人）。
加"≥2 篇"后降到 3,542 人——仍然很多，但至少不是"蹭一次署名"。

### 4. 结果

| 指标 | 扩张前 | 扩张后 |
|---|---|---|
| 人物 | 36,122 | **40,780** |
| 已发布专家 | 4,817 | **8,262** |
| 论文 | 8,007 | **8,944** |
| 共著边 | 88,686 | **93,496** |
| 库大小 | 336 MB | 350 MB |

专家墙"按网络筛选 + 按合作强度排序"（`/experts?near=527&sort=network`）：


这才是"合作强度"该有的样子——之前权重全是 1，看不出亲疏。

## 一个真实的回归（必须记下来）

语料扩张后，检索评测 nDCG 掉下来了：

| 配置 | 扩张前 | 扩张后 |
|---|---|---|
| bm25 | 0.2354 | **0.1737**（−26%） |
| dense | 0.0645 | 0.0645（不变） |
| rrf_k60 | 0.1987 | 0.1880 |

**原因**：新增了 938 篇同一个团队的论文、约 4,700 个新人物，
而 gold set 是固定的人物级集合——分母变大、竞争变强，nDCG 自然下降。
向量通道不变，因为它只索引 published 人群的画像（数量变化相对小）。

这不是"代码坏了"，而是**评测口径与语料规模绑定的副作用**。
诚实做法：基线已重录（`eval/baseline.json`），并在报告里写明"0.1737 是新语料下的基线，
不能和 0.2354 直接比"。

## 前端接线

- 图谱页新增按钮「在专家墙看这些人」→ 跳到专家墙，带上 `near=<pid>`，强制按共同论文排序；
- 专家墙顶部出现筛选条：`网络：pid 527 的合作者（共 3542 人，按共同论文排序）`，可一键清除；
- 卡片上多一个「共同论文 N」徽章。

## 遗留问题

1. **发布集被"网络背书"稀释了**：4,817 → 8,262，新进来的 3,445 人里绝大多数
   只是"和钟南山合作过 ≥2 篇"。浏览专家墙的普通用户看不出这个差别。
   下一步应该给卡片打「网络来源」标记，或让默认视图排除网络背书的人。
2. **只扩张了一个人**：换成某学术图谱 483 人的任何一个，都能用同一条命令
   （`python -m app.expand_author --pid X --openalex AXXXX`）。
3. **请求成本**：一个人约 6 + 98 = 104 次 OpenAlex 请求。无 key 的日预算 1,000 次，
   一天最多扩 9~10 个人——这是硬约束，扩 483 人需要 50 天或申请 API key。
