# M26：问答引导（Agent 先开口）

## 问题

用户进「Agent 问答」看到的是一个空输入框，不知道该问什么、也不知道能问到什么程度。
空白输入框是最差的产品形态。

## 做法

### 1. 后端：`GET /chat/welcome`（纯数据，无模型调用）

```json
{
  "greeting": "我是 ScholarTrust 的学者尽调助手。先说清楚我的底子：库里 47,569 位学者、
               11,104 篇论文，其中 102 位有完整成果档案；我不接大模型…",
  "stats": {"people": 47569, "works": 11104, "dossiers": 102, "with_zh_name": 15},
  "groups": [
    {"title": "认识一位专家", "examples": ["介绍一下钟南山", "钟南山的研究方向", …]},
    {"title": "看他们的关系", "examples": ["钟南山和李兰娟的关系", "谁和钟南山合作过"]},
    {"title": "对比两位专家", "examples": ["比较钟南山和李兰娟近五年的研究方向差异"]},
    {"title": "找审稿人",     "examples": ["谁更适合审一篇关于肺癌免疫治疗的稿件"]},
    {"title": "按主题找人 / 找论文", "examples": ["找研究 dementia 的专家"]}
  ],
  "limits": ["不接大模型…", "深档案只有 102 位…", "中文语义检索较弱…", "中文名覆盖有限…"]
}
```

两个关键约束：

1. **示例必须真能跑通**：`_runnable()` 会检查示例里提到的人是否在库里有中文名，
   跑不通的例子直接不展示——宁可少列，不列假的。
2. **主动写边界**：四句话说明"我不是大模型、深档案只有 102 位、中文检索弱、中文名少"。
   承认限制比多列三个功能更能建立信任。

### 2. 前端：进「Agent 问答」页时自动出现

- 开场白 + 统计数字；
- 五组示例，**每个都是可点的按钮**，点一下直接发送；
- 末尾列出四条能力边界（灰色小字）。

只显示一次（同一次会话），避免每次切换都刷屏。

## 顺手修的一个路由 bug

"谁更**适合**审一篇…" 被路由到了 `compare`——因为 `_CN_COMPARE` 里有 `谁更`，
而 `_CN_REVIEW` 判断在它后面，且当时根本没有 review 分支。

修复：
1. `_CN_REVIEW`（审稿|审一篇|评审|reviewer）**提到最前面**；
2. 审稿问题不再走单轮工具，而是**调用多步尽调任务**（`tool_task`），
   复用 researcher/analyst/verifier，并把报告原文作为回答返回。

这也让聊天和尽调页共用同一套能力，不再各写一套。

## 还没做的

1. **示例写死在代码里**：不能按用户画像/历史动态推荐。真正的引导应该"看你上次问了什么，
   这次换个角度"。
2. **没有"示例跑不通"的自动巡检**：现在是人工跑一遍，应该把这个测试接进回归
   （`app/regression.py` 目前只覆盖 24 道题，不含 welcome 示例）。
3. **限制说明是静态文案**：如果深档案从 102 涨到 500，这段字不会自动更新。
