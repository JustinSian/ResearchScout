# M46：verifier 的故障注入实验（多智能体内部唯一没量化的部分）

## 问题

task 流程是 researcher → analyst → verifier 三角色协作，但前面只量化了
"supervisor vs 单 agent"（m45），**task 内部这三个角色到底谁在起作用，一直没测**。

其中 verifier 最该测：它负责"每条结论能不能回溯到库里的字段/边/标题"。

## 做法：故障注入

不用 LLM，所以不能靠"等模型说错话"。改用**受控篡改**：

| 步骤 | 说明 |
|---|---|
| 1. 造干净 claim | 从真实档案取 metric（works/cites/h_index）、term（论文标题里的词）、domain（此人近五年真实主题词）、coauthor（真实边权重） |
| 2. 注入错误 | **无意义型**：数值 +1、术语换成 `zzz...`、主题换成 `medieval/poetry`、共同论文数 +3<br>**跨人型**（更难）：主题换成**另一个人的真实主题词**——词是真的，只是不属于这个人 |
| 3. 喂给 `subagents.verifier` | 统计检出率 / 误报率 / 耗时 |

对照组 = "没有 verifier"：所有 claim 直接通过，检出率恒为 0。

## 结果

```
干净 15 条        → 误报 0%（通过 100%）
无意义注入 15 条  → 检出 100%（四类全 100%）
跨人注入 15 条    → 检出 93%（coauthor 100% / metric 100% / term 100% / domain 67%）
每 100 条耗时 201ms
```

### 两个数字值得说

**1. 误报率 0%**：verifier 没把任何干净 claim 判错。
（第一版实验误报 20%，查下来是**我的测试错了**——我给所有人都硬编码了 `asthma/copd`，
李兰娟是肝病/肠道菌群，当然对不上。改成"每人自己的真实主题词"后归零。
教训：误报先怀疑测试构造，再怀疑检验器。）

**2. 跨人注入只有 domain 掉到 67%**：把 A 的领域词换成 B 的真实领域词后，
有 1/3 没被抓到。原因很直接——**同一领域的人主题词高度重叠**：
钟南山和李兰娟的论文标题里都有 `patients`、`clinical`、`cohort` 这类词，
"标题里含这些词"这个判据分不出"是不是这个人"。

这不是 bug，是**判据的能力边界**：`domain` 检查的是"此人作品里有没有这些词"，
而不是"这些词是否属于此人"。要抓跨人混淆，需要更强的信号（作者身份一致性、
合作者重叠、机构一致性），不是调阈值能解决的。

## 复现

```bash
python -m app.ab_verifier                    # 默认取 3 位档案量最大的人
python -m app.ab_verifier --pids 527,503,628 --n 5
```

## 测试

`tests/test_ab_verifier.py`（6 项）：干净 claim 不被改、四类注入确实改变关键字段、
跨人注入用对方主题词、缺参数时回退到无意义词。全量 **153 项**通过。

## 遗留

1. **样本小**（15 条 / 3 人），跨人 67% 的置信区间很宽；
2. 只测了 verifier，**researcher / analyst 的单独贡献没测**——那需要更细的中间产物对照；
3. 注入的是"claim 层"错误，没有模拟"报告文字与 claim 不一致"这类生成层错误；
4. 没有测"verifier 拦下之后流程怎么降级"（当前是进 rejected 列表，报告仍会生成）。
