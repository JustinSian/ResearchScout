# M8：图分析（社区 / 路径 / 机构网）

## 为什么不建图数据库

用户建议"创建图数据库"。**没有做，理由是实测的**：

| 需求 | SQLite 现状 | 是否够用 |
|---|---|---|
| 1~2 跳邻居 | 递归 CTE，`/graph/122?depth=2` 50 节点 200 OK | 够 |
| 最短合作链 | 双向 BFS，1 跳实测返回 | 够 |
| 机构聚合 | 全量读边（8.8 万条）在内存里算，<1s | 够 |
| 社区划分 | networkx Louvain，23,116 节点 / 88,551 边，~10s 离线 | 够 |

而且这台机器**没有 docker、没有 sudo**，Neo4j 装不了。引一个图数据库只会增加部署成本，
不解决任何当前问题。真正的短板是"图上没有分析"，所以补的是分析而不是存储。

## 加了什么

### 1. 社区划分（Louvain）

| 指标 | 数值 |
|---|---|
| 节点 / 边 | 23,116 / 88,551 |
| 连通分量 | 3,048 个（最大 5,657） |
| 社区数 | **3,081** |
| 最大社区 | **746 人** |
| 模块度 | **0.983** |

第一版用自己写的标签传播（LPA），结果是 **4,027 个社区、最大只有 59 人**——
在同篇论文形成的团结构上，LPA 会退化成"每篇论文一个社区"。
换 networkx 的 Louvain 后最大社区 746、模块度 0.983，才是有意义的划分。

抽样：Bengio 在社区 36（73 人）、Hinton 在社区 46（51 人）——
两人确实不在同一个合作圈里，与"4 跳内不连通"的实测一致。

### 2. 最短合作链（双向 BFS，最多 5 跳）

```
/graph/path?a=27&b=29  → hops=1  Ahmedin Jemal → Rebecca L. Siegel
/graph/path?a=122&b=17 → 5 跳内不连通（Bengio 与 Hinton 在样本内没有共同论文链）
```

后者不是 bug：用真实存在的边测试时 hops=1 正常返回，所以是数据事实。

### 3. 机构级关系网

```
/graph/institutions?top=20 → 20 节点 / 123 边
最大机构：Harvard University（172 位发布专家）
最强边：Broad Institute — Harvard（14 篇共同署名）
```

## 前端：Canvas 力导向图

原来是 SVG 环形布局（节点多了就挤）。改成：

- **Canvas + 自写力导向**（斥力 + 弹簧 + 向心 + 阻尼），可拖动节点、悬停出 tooltip、点击打开画像
- **三种模式**：合作网络（ego，1/2 跳）/ 机构网络 / 两人路径
- **三种着色**：按机构（默认）/ 按社区 / 按影响力（被引取 log 映射到色相）
- 图例显示 top 社区及人数；路径模式把链路列出来，每个名字可点

默认按机构着色，是因为实测 1 跳和 2 跳的 ego 网络**整张图都在同一个社区**（社区就是围绕他形成的），
按社区着色会是一片同色，没有信息量。

## 踩的坑

1. `/graph/{pid}` 会把 `/graph/path` 吃掉 → 改成 `/graph/{pid:int}` 用 int 路径转换器；
2. 社区着色对 ego 图无效（见上）→ 增加着色模式并默认按机构；
3. 第一版 LPA 划分过碎 → 换 Louvain。

## 接口

```
GET /graph/{pid}?depth=1|2        合作网络（节点带 community/csize）
GET /graph/path?a=&b=&max_depth=  最短合作链
GET /graph/institutions?top=N     机构级关系网
GET /graph/community/{pid}        某人所属社区及规模
```
