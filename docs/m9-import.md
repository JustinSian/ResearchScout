# M9：接入某学术图谱专家库（钟南山）+ 多源采集怎么落地

## 做了什么

把某学术图谱（10.x.x.x）专家库里的**钟南山**记录接进 ScholarTrust，并且**不绕过可信门槛**。

### 数据从哪来

某学术图谱的后端接口（`:<port>`）没有专家接口（64 个路径里只有 kb/graph/retrieval），
所以直接读它的 PostgreSQL：

```
容器 huafu-postgres → 库 huafu_rag → 表 experts
字段：id, name, title, affiliation, metadata(jsonb), ...
```

用 `jsonb_build_object` 只导需要的字段（姓名/英文名/单位/头衔/关键词/研究方向/代表作），
整行记录有几十 KB 的画像 JSON，全量拉会污染管道。

### 关键发现：他已经在库里了

OpenAlex 里他叫 **Nanshan Zhong**（pid=527，2 篇，已发布），而且 **OpenAlex 把同一个人拆成了两条**
（pid=527 已发布 / pid=31690 被拒）。某学术图谱提供的是第三条记录（中文名 + 头衔 + 7 篇近作）。

所以正确动作不是"新增"，而是**跨源合并**：

| 步骤 | 结果 |
|---|---|
| 去重（英文名 + 机构 → 英文名唯一 → 中文名） | 命中 pid=527 |
| 合并（搬论文/合作边、并主题、删多余记录） | 31690 → 527 |
| 最终 | **1 条记录**：钟南山 / Nanshan Zhong，10 篇论文，可信度 1.00，来源 huafu |

### 门槛怎么给分

新增两条证据，不修改原有权重结构：

| 证据 | 分值 | 理由 |
|---|---|---|
| `chinese_person_name`（2~4 个汉字） | +0.20 | 中文人名形态 |
| `external_verified_source`（外部库已核验） | +0.55 | 来源可信度，但低于主库可测产出 |
| `has_headline`（有头衔/职位） | +0.10 | 记录完整度 |
| `non_person_word_zh`（大学/医院/研究院…） | −0.55 | 中文机构名不能被当人名 |

实测：

```
钟南山 + 外部核验      → 1.00 accept
钟南山 无外部核验      → 0.70 review   ← 只有中文名和机构不够
广州市第一人民医院     → 0.25 reject
呼吸疾病研究团队       → 0.15 reject
Geoffrey Hinton        → 0.80 accept   ← 原有行为未受影响
```

## 多源采集怎么用现在这套系统做

### 一条流水线（所有来源共用）

```
外部源 → 适配器(adapter) → 规范化记录 → 去重 → 可信打分 → 发布/待审 → 留痕
                                   ↑                    ↓
                              人工复核队列 ←────────────┘
```

新增一个来源只需要写一个 `normalize_xxx()`：把该源的字段映射到
`{name, name_zh, last_inst, headline, topics, works_count, cited_by_count, papers, external_verified, source_ref}`，
其余全部复用。

### 已经具备的四个部件

| 部件 | 位置 | 作用 |
|---|---|---|
| 适配器 | `app/import_external.py::normalize_hf` | 某学术图谱 → 标准记录 |
| 去重/合并 | `_dedup()` / `merge_people()` | 同名多源合并，搬论文与边 |
| 可信门槛 | `app/judge.py` | 外部来源作为一条证据参与打分 |
| 留痕 | `candidates` + `review_queue` | 每条导入都能追溯来源与理由 |

### 命令行

```bash
# 导入一份规范化记录
python -m app.import_external data/imports/huafu_zhong.json

# 合并同名记录（OpenAlex 会把同一人拆成多个 author id）
python -m app.import_external --merge-name "Nanshan Zhong"
```

## 遗留问题

1. **合作边没接**：某学术图谱记录里的"合作"是机构/平台（广州实验室、国家呼吸医学中心），
   不是人。我们的 `edges` 只连人，所以他的合作者数是 0。要做的话得引入"机构节点"类型。
2. **中文检索是词面匹配**：`钟南山` 能命中，但"呼吸领域的院士"这类中文语义查询仍不行——
   向量模型是英文的 bge-small-en。
3. **只导了 1 个人**：某学术图谱 483 人还没批量导入，目前是打通链路 + 验证一个样本。
