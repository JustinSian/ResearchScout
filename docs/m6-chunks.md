# M6：chunk 级检索（做了，但结论和预期相反）

## 做了什么

- 摘要按句切块：**28,405 块 / 8,000 篇（平均 3.6 块/篇）**，FTS5(porter) + 向量表结构就绪
- 检索链路：chunk 命中 → 聚合到论文 → 聚合到作者
- 在同一批 gold set 上做三方对比：人物索引 / chunk 索引 / 两者 RRF 融合

**硬约束**：OpenAlex 不返回全文，只有摘要。某学术图谱有 30,984 个 chunk 是因为它存了 PDF 全文；
本项目这一轮只能在摘要级做，所以块均 3.6 个/篇，而不是 8 个/篇以上。

## 结果一：chunk 检索对实体查询是退化的

| 配置 | name | institution | topic | 总体 nDCG |
|---|---|---|---|---|
| 人物索引 BM25 | **1.000** | **0.357** | 0.037 | **0.348** |
| chunk 索引 | 0.133 | 0.048 | **0.226** | 0.112 |

差值（chunk − 人物）：**−0.237，CI [−0.335, −0.137]，显著下降**。

原因清楚：人名和机构名不在摘要里，chunk 索引天然拿不到这些信号；
只有在 topic 类查询上，chunk 才把 0.037 拉到 0.226。

## 结果二：融合是"第三处标签泄漏"

第一眼看起来融合有效：

| gold 集 | 人物 | 融合 RRF | 差值 | 判定 |
|---|---|---|---|---|
| gold.json（真值按被引 top5） | 0.348 | **0.391** | **+0.043** | CI [+0.009, +0.080] **显著提升** |
| gold_alt.json（真值随机抽 8 人） | **0.240** | 0.183 | **−0.056** | CI [−0.084, −0.028] **显著下降** |

同一个改动，在两套真值上给出**方向相反且都显著**的结论。
和 M2 的"权威性先验"、M3 的"门槛精度"是同一个病根：**按被引排序的真值会把任何
"偏向高被引/热点"的改动判成利好**。

## 结论：chunk 不用于排序，只用于引用

- 专家排序继续用人物索引（BM25，加查询松弛）；
- chunk 索引的唯一价值是**句子级证据**——回答里能写出"原文哪句话支撑这个结论"，
  这是人物卡片做不到的。

已落地到 Agent：`find_expert` 返回前 3 位专家时附带 `passages`（该专家命中句块的原文），
回答里长这样：

```
1. **Laurence Zitvogel** — Inserm；样本内 3 篇 / 被引 13,950
   > 证据（2017《Gut microbiome influences efficacy of PD》）：Resident gut bacteria
     can affect patient responses to cancer immunotherapy…
```

## 如果要做真正的 chunk 级 RAG，还缺什么

1. **全文**：得走 arXiv / PMC / OA PDF（OpenAlex `best_oa_location.pdf_url`），
   每条要下载+解析，8000 篇里有 OA 全文的估计三到五成；
2. **chunk 质量**：按章节/段落切，而不是按句号硬切；
3. **重排**：chunk 召回后用 cross-encoder 重排再给 LLM，而不是直接给 BM25 分。

这三件事都还没做，报告里不声称"已实现 chunk 级 RAG"。
