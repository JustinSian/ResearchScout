# M44：答案级评测（以及它揪出的 4 个路由 bug）

## 为什么要做

原来的评测只到两层：

| 层 | 指标 | 问题 |
|---|---|---|
| 检索 | nDCG@10 | 只管"文档排序"，不管回答 |
| Agent | 工具选择 / 是否拒答 / 是否带引用 | **答错名字、说反数字，照样满分** |

所以补一层**答案级**评测：gold set 写"这个回答必须包含什么、不能包含什么"。

## 设计

`eval/answers.jsonl`（20 条），每条是一个约束对象：

```json
{"id":"facet-cn-hospital","q":"中国的医院里的呼吸专家",
 "tools":["find_expert"], "must_any":["医院"]}
```

判定项（全部机械可判）：

| 项 | 含义 |
|---|---|
| `tools_ok` | 首个工具是否等于期望 |
| `refuse_ok` | 该拒的拒了、不该拒的没拒 |
| `kb_refuse_ok` | 库内是否拒答（为真时允许随后联网兜底） |
| `cited_ok` | 非拒答必须带引用（拒答不需要） |
| `must_any_ok` | 至少命中一个期望片段（同义写法，不锁措辞） |
| `must_all_ok` | 全部期望片段都要出现 |
| `must_not_ok` | 禁止出现的片段 |

支持多轮：`turns` 依次发送（共用 `sid`），只评最后一轮。
评测走 **`supervisor.run`**，即用户实际拿到的那条链路（含路由与联网兜底）。

## 结果：55% → 100%，中间修了 4 个真 bug

首轮基线 **55%（11/20）**。9 个失败里，5 个是评测口径问题，**4 个是代码 bug**。

### bug 1：`引用最多的呼吸专家` 被当成"引用链"

`_CN_CITE` 匹配到"引用"，直接路由到 `citations` 工具——但这是**排序问题**。

修：新增更严的 `_CITE_CHAIN`（引用了谁 / 谁引用了 / 引用链 / 两跳），只有它才走引用工具。

### bug 2：纯中文问题被 `latin_query` 清空

`latin_query("引用最多的呼吸专家")` → `""`，空检索必然 0 结果 → 拒答 → 联网。

修：`q_en` 为空时回退用原文。

### bug 3：纯中文主题问题走交叉编码器，查不到英文标题

`"呼吸专家"` 没有硬条件（国家/机构/被引），所以走 CE 路径；但 CE 拿中文查英文语料 → 0。

修：**无拉丁词 + 有可翻译主题** → 走 facet 检索（主题已由词表翻成英文）。
含英文的问题仍走 CE，避免影响原有英文查询质量。

### bug 4：`extract_names` 把中文残留当人名

```
"谁和钟南山一起写论文"   → ['钟南山一', '一起写']   → 路由成 relation
"介绍某领域的带头人"     → ['带头人']              → 路由成 profile
```

修：**中文候选必须"库里真有这个人"**（`name_zh` 或 `name` 命中才保留）。
比堆停用词可靠——停用词永远列不完。

### 另外：回显改成中文

原来回显是 `机构类型=hospital`、`国家=CN`。现在映射成 `机构类型=医院`、`国家=中国`。

## 顺带修正旧评测的口径

`app/agent_eval.py` 里"应拒答"的判定用的是最终 `refused`，
但接入 AnySearch 兜底后，库内拒答会被网络答上 → 判定失败。

修：改用 `answer(q, allow_fallback=False)`，测的就是**库内**能力。

## 最终

```
答案级评测：20/20 = 100%
  延迟 p50 121ms / p95 4.5s（p95 被联网兜底那两条拉高）
旧工具回归：工具 100% / 拒答 100% / 引用 100% / 数字 100%
全量测试：142 项通过
```

## 局限（重要）

1. **只有 20 条**，覆盖新功能（facet/引用/多轮）但不算充分，容易被针对性调优；
2. **约束是子串匹配**，语义等价但换个说法就判失败（例如"呼吸科"vs"呼吸"）；
3. **没有 judge 模型**：判断题靠规则，判断不了"数字说反了但格式正确"这类错误；
4. 没有跑多次取稳定性（温度=0，但联网兜底会受外部结果影响）。

## 下一步（如果要继续加证据）

- 把 20 条扩到 60 条，并按功能分层统计（facet / 引用 / 多轮 / 拒答）；
- 数字一致性检查：回答里的"被引 N"必须能在 `people.cited_by_count` 找到；
- 引入 LLM-as-judge 做语义等价判定（需要额外模型，成本另算）。
