# M31：多轮上下文（"那这些人里谁被引最高"）

## 问题

收窄按钮能一层层筛，但每轮都是**独立解析**。用户接着说：

```
那这些人里谁被引最高？
他们谁论文最多？
```

这两句里没有任何实体，"这些人"指谁只有上一轮知道。按原来的实现，
`latin_query()` 会把中文全删掉、路由还会判定"没有实体"转去网络检索。

## 做法：存结构化上下文，不塞提示词

我们的答案链路是确定性的（解析 → 过滤 → 排序），所以上下文只需要三样东西：
上一轮的 **pid 集合**、**条件**、**时间**。存在 SQLite 里（`chat_ctx` 表），
按前端生成的 `sid` 索引。

```
前端 sessionStorage 生成 sid → /chat?q=...&sid=s-xxxx
     ↓
supervisor.run(query, sid) → context.resolve()
     ↓ 有指代词且有上一轮 → inherit
tool_find_expert: facets["pids"] = 上一轮的 pid → SQL "p.pid IN (...)"
```

代价是**没有 LLM 也能多轮**：指代 = 集合继承，排序 = 换个 ORDER BY。

## 三个必须踩过才知道的坑

**1. `plan_node` 的 `latin_query()` 会把指代词删掉**
"他们谁论文最多" → 只剩 "论文最多" → 上下文断掉。所以含指代的句子必须传原文。

**2. "论文"会抢先命中关键词分支**
`_CN_WORKS` 匹配到"论文"，直接走论文检索工具，返回空 → 拒答 → 转网络。
指代判断必须放在所有关键词分支**之前**。

**3. 路由会把指代问题判成"无实体 → 联网"**
supervisor 的 `decide()` 看到"谁被引最高"没有实体，默认转 web。
现在 `run()` 先看上下文：有继承就强制走 kb，不进路由。

## 诚实的边界

**"谁最年轻"答不了**——库里没有出生年份，只有被引/作品/h-index。
所以问"年轻"时会明确说明：

```
库里没有出生年份，无法按年龄排序；这里按最近活跃度排。
```

不假装能算年龄，是这类系统最容易越界的地方。

另外：**没有上下文时的指代会要求澄清**，而不是猜：

```
我没法确定"这些人"指的是哪一批——上一个问题可能已过期，或者换了会话。
请把条件再说一次，例如"中国的呼吸科专家"。
```

## 实测

| 轮次 | 输入 | 结果 |
|---|---|---|
| 1 | 中国的呼吸科专家 | 22 人（展示 10），Capital Medical University 9 人 |
| 2 | 那这些人里谁被引最高 | 在这 **10** 人里按被引排序 → Bo Yang 49,162 |
| 3 | 他们谁论文最多 | 在这 **10** 人里按作品数排序 |
| 4（换 sid） | 那这些人里谁被引最高 | 要求澄清，不瞎猜 |

## 实现清单

- `app/context.py`：`chat_ctx` 表、`has_anaphora()`、`sort_hint()`、`resolve()`、`save()/load()/clear()`
  - 30 分钟没说话视为新会话；最多保留 60 个 sid
- `app/facets.py`：`search()` 支持 `pids` 过滤（最多 200 个）
- `app/agent.py`：`tool_find_expert(query, sid)` 继承上下文；`plan_node` 指代优先
- `app/supervisor.py`：`run(query, sid)`，指代强制 kb；无上下文要求澄清
- `app/api.py`：`/chat` 与 `/chat/stream` 接受 `sid`
- `web/index.html`：sessionStorage 生成 `sid` 并随请求带上
- `tests/test_context.py`：6 项（指代识别、排序意图、无会话不继承、年轻不撒谎、往返存取）

## 遗留

1. **上下文只存 pid 集合，不存"话题"**：如果第二轮换了话题又说"他们"，会继承错；
2. **没有跨会话记忆**（换浏览器就丢）；
3. **指代词表是硬编码的**（这些人/他们/上述…），方言和口语覆盖不全。
