# M7：全文 chunk 级检索（最终版：396 篇全文）

## 全文从哪来

| 来源 | 可用 | 已下载 | 覆盖率 |
|---|---|---|---|
| arXiv | 323 | 322 | **100%** |
| 其他 OA PDF | 2,106 | 74 | 4% |
| 无全文 | 5,571 | — | 高被引的 Nature/Science 多数没有 OA |

- 抓取方式：OpenAlex `locations[]` → 取 arxiv.org 链接 / OA `pdf_url`（40 次 API 额度）
- 下载：校验 `%PDF` 魔数，**丢弃约 25% 的 HTML 拦截页**（实测 `nature.com/*.pdf` 返回 `text/html`）
- 解析：PyMuPDF，平均 **10.7 万字符/篇**
- 其他 OA 站点的成功率很低（超时/防盗链），这是只拿到 74 篇的原因

## 建索引

全文按段落切块，**去参考文献段**（否则 chunk 里全是作者名和年份，会被当成证据）：

| | 块数 |
|---|---|
| 全文块（396 篇） | 26,300 |
| 摘要块（7,604 篇） | 27,000 |
| 合计 | **53,300**（平均 6.7 块/篇） |

## 评测：两个口径 × 两套真值

| gold 集 | 口径 | 人物索引 | chunk 索引 |
|---|---|---|---|
| gold_alt（随机真值） | 全库 (n=50) | **0.240** CI[0.18,0.30] | 0.031 CI[0.02,0.05] |
| gold_alt（随机真值） | 有全文子集 (n=21) | **0.157** CI[0.09,0.24] | 0.046 CI[0.01,0.09] |
| gold.json（按被引真值） | 全库 (n=100) | **0.348** CI[0.26,0.44] | 0.133 CI[0.09,0.18] |
| gold.json（按被引真值） | 有全文子集 (n=33) | 0.130 CI[0.05,0.23] | **0.207** CI[0.12,0.31] |

**读法**：在**不按被引排序**的真值上，chunk 无论全库还是子集都大幅落后；
只有在**按被引排序**的真值 + 有全文子集时 chunk 才反超，且主要是
collaborator（0.306 vs 0.000）和 topic（0.235 vs 0.027）两档。

**这是第四次出现同一模式**（M2 权威先验、M3 门槛精度、M6 摘要 chunk 融合、M7 全文 chunk）：
按被引构造的真值，会系统性把"偏向热点"的改动判成利好。

## 结论

1. **chunk 级全文检索不用于专家排序**——加入全文没有改变这个结论；
2. chunk 的价值是**句子级证据**：块更大（600~900 字符）、有上下文，
   回答里能引"原文哪句话支撑这个结论"；
3. 覆盖面是硬伤：只有 **5%** 的论文有全文（396/8000），
   所以不声称"已实现全文 RAG"，只声称"对 396 篇做了全文索引，用于证据引用"。

## 顺带发现

- OpenAlex 的 `best_oa_location.pdf_url` 大面积是 null（实测 Nature 那篇只有 landing page），
  必须扫 `locations[]` 才能拿到 arXiv 链接；
- 高被引论文反而最拿不到全文——付费墙与"经典论文"高度重合，
  这对"先抓高被引再补全文"的策略是个结构性限制。
