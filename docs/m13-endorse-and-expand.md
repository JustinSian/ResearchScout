# M13：给"网络背书"打标 + 再扩两个种子

## A. 区分"独立核验"与"仅靠网络背书"

### 为什么要分

M12 扩张后发布集从 4,817 涨到 8,262，其中绝大多数只是"和钟南山合作 ≥2 篇"。
浏览专家墙的人看不出差别——这等于把门槛的作用稀释掉了。

### 第一版做错了

我最初的定义是"**用过**网络背书这条证据就打标"，结果：

```
钟南山网络内：独立核验 0 人 / 网络背书 3542 人
```

显然不对——里面很多人本身就有几十篇论文和机构，没有扶持也能过。

### 正确口径（离线重算，不耗 API）

把 `coauthor_of_verified` 从特征里**去掉再判一次**：

| 去掉后仍然 accept | 标记 |
|---|---|
| 是 | `endorse = NULL`（独立核验） |
| 否 | `endorse = 'network'`（仅靠网络） |

结果：

```
靠自己达标 1,363 人 / 仅靠网络 268 人
全库已发布 8,490：独立 8,252 / 网络背书 238
钟南山网络内：独立 3,333 人 / 网络背书 209 人
```

### 落地

- 新列 `people.endorse`（`db.py` 里做成幂等迁移，不再散落在各脚本）；
- `/experts?endorse=verified|network` 可筛选；
- 专家墙加「全部背书 / 仅独立核验 / 仅网络背书」下拉；
- 卡片上打「网络背书」橙色徽章。

### 成本控制

新的 `--max-enrich N` 只补"共同论文最多"的前 N 人：

```
李兰娟：6 页论文 + 150 人档案 = 9 次请求
何建行：6 页论文 + 150 人档案 = 9 次请求
```

从"每人约 104 次"降到"每人约 10 次"。

## C. 顺手修的一个中文硬伤

**"介绍一下李兰娟"查不到人**——`name_zh` 只有从某学术图谱导入的钟南山有，
OpenAlex 的人只有英文名。用户是中文用户，这个不能忍。

新增 `person_alias(pid, alias)` 表 + 一份**人工整理**的别名（只收有把握的）：

```
Lanjuan Li → 李兰娟      Jianxing He → 何建行
Kefang Lai → 赖克方      Pixin Ran → 冉丕鑫
Zifeng Yang → 杨子峰     Jinping Zheng → 郑劲平
Wenhua Liang → 梁文华    Ruchong Chen → 陈荣昌
Yimin Li → 黎毅敏        Nanshan Zhong → 钟南山
```

别名同时写进 FTS 与 `name_zh`，所以：

```
介绍一下李兰娟 → **李兰娟**（浙江大学附属第一医院） 1,174 篇
何建行是谁     → **何建行**（广州医科大学附属第一医院）1,038 篇 / 被引 68,582
```

**注意**：这是人工别名，不是 OpenAlex 数据。以后从某学术图谱批量导入时，
`metadata.name_en` + `name` 可以自动生成别名，就不需要这份表了。

## D. 又一次评测回归

语料从 8,944 篇涨到 11,104 篇，检索基线继续下降：

| 配置 | 扩张前 | 现在 |
|---|---|---|
| bm25 | 0.2354 | **0.1699** |
| dense | 0.0645 | 0.0645 |
| rrf_k60 | 0.1987 | 0.1888 |

原因同 M12：**gold set 是固定的人物集合，语料变大 → 竞争变强 → nDCG 下降**。
基线已重录。这条要写进简历时得解释清楚，否则会被误读成"检索变差"。

## 遗留

1. **别名只有 11 个**：中文提问只能覆盖这几位，其余中文名仍查不到。
   根治办法是从某学术图谱 483 人批量导入（带 `name_en`），自动产生别名。
2. **网络背书 238 人**：数量已可控，但仍建议在专家墙默认视图里排除（现在是"全部"）。
3. **三人网络高度重叠**（都在广州呼吸圈），图谱会挤成一团；跨圈扩张（如计算生物学、
   物理）才能看出社区结构，但那会稀释领域相关性——是产品取舍。
