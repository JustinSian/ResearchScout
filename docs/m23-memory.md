# M23：记忆层（任务缓存 + 档案变更 diff）

## 两个需求

1. **同一问题问第二次，不该重跑**（重复尽调是浪费）。
2. **同一专家再看一次，要能说出"他变了什么"**（这是"长期经验沉淀"的实际含义）。

## 数据结构

```sql
kv(key, value_json, updated_at)          任务级缓存
dossier_change(cid, pid, ts, diff_json)  档案快照差异
```

## 关键设计：缓存带语料版本

```python
{"tid": 20, "report_path": "/reports/20.md",
 "version": {"works": 11104, "dossiers": 102}}
```

取缓存时比对当前 `corpus_version()`。**语料一变，缓存自动作废**——
否则用户会拿到基于旧语料得出的结论，这比慢更糟。

## 实测

```
第一次：tid=20  cached=False  1992 ms
第二次：tid=21  cached=True     65 ms   复用 #20
提速 31×
```

缓存命中时不会假装"重新算过"：任务页显示绿色徽章
「记忆命中 · 复用 #20」，`/tasks` 里也能看到这一步的 tool 是 `memory`。

## 档案变更 diff

`build_dossiers` 建完档案后与上一次快照比对，只记录**变化**：

```json
{"works": {"from": 1174, "to": 1177, "delta": 3},
 "h":     {"from": 117,  "to": 118,  "delta": 1},
 "new_venues": ["Journal of Hepatology"]}
```

画像页的「深档案」卡片会显示一行：
`记忆层：上次建档后 works +3、h +1`。

## 接口

```
GET /memory                  缓存规模 + 当前语料版本
GET /dossier/{pid}/changes   某位专家的变更历史
```

## 三个诚实的限制

1. **缓存键是"意图+问题文本"**：换个说法（"钟南山和李兰娟的差异" vs "比较钟南山和李兰娟"）
   就会 miss。语义缓存需要向量近似，没做。
2. **diff 只在"重建档案"时产生**：日常不会自动检测新论文，需要定时跑
   `build_dossiers --force`。现在没有调度器（健康检查有守护进程，建档没有）。
3. **缓存不过期（只随语料失效）**：如果一个专家的档案被修正但语料总量不变
   （例如修数据），缓存不会失效。这是真实的漏洞。

## 对照规划

| 规划项 | 状态 |
|---|---|
| 短期上下文（任务内） | ✅ 虚拟文件系统 + 摘要 |
| 长期记忆（跨会话） | ✅ 任务缓存 + 档案快照 |
| 变更 diff | ✅ 有，且能在 UI 看到 |
| Redis / Milvus | 未用；SQLite 足够单机演示 |
