# M57：跨用户经验记忆 + 科研库自动扩充

## 两个问题的答案

**问题 1：成功的科研搜索，能不能存成"经验"给别的用户用？**
能。新增 `search_episode` 表：每次成功链路记录「归一化问题 + 主题 + 工具序列 + 命中专家 + 成本」。
下一个用户问同类问题时，这段经验会注入 Agent 的 system prompt：

```
【同类检索经验（其他用户跑通过的路线）】
- 类似问题「gaucherdisease」：工具 find_expert→profile→research_area，
  命中 4 位（pid: 47592,47594,47595,47593）
```

**问题 2：库里没有相关专家时，能不能自己去采集？**
能。`app/expand.py`：主题 → OpenAlex `/works?search=` → 验证 → 入库 → 补 FTS → 自动重试一次。
用户感知：「这次没有 → 已为你扩充 4 位该领域专家 → 重试后给出结果」。

## 关键设计

### 经验只在"真相关"时写入

写经验的门槛不是"回答看起来像成功"，而是**结果的专家标签必须匹配主题**（`topic_match.matches`）。
否则会把"查不到却答得像样"的路线固化下来，污染后续所有用户。

### 扩充的验证：标题匹配 ≥2 篇

第一版直接信 OpenAlex 的 `search` 排序，结果把 **Vapnik、Weston 这些 ML 学者**标成了
"Gaucher disease 专家"——因为他们的 SVM 论文用了 Gaucher 数据集，摘要里出现了这个词。

修复：
1. 论文必须**标题**包含主题（不用摘要，"需与 Niemann-Pick 鉴别"也会命中）；
2. 同一作者至少 **2 篇**标题命中（样本少时放宽到 1 篇）；
3. 只有验证通过的作者才打主题标签、才发布；否则 `pending` 进复核队列；
4. `audit_expansions()` 定期审计：标签写了但论文不匹配 → 摘标签 + 降级 + 从 FTS 移除。

### 新入库必须同步 FTS

`people_fts` 是外部内容表，只 insert `people` 不会自动进索引——
第一版扩充完"新增 5 人"，但 `search_people` 一个都搜不到。现在 `_index_person()` 显式维护，
并给历史数据补索引（一次补了 15 位）。

## 实测

| 动作 | 结果 |
|---|---|
| Gaucher disease 扩充 | 4 位脂质沉积病学者，检索可命中 |
| Niemann-Pick（严格标题后） | 1 人 / 10 篇（**宁可少收**） |
| 误标审计 | 24 人保留、**6 人降级**（首批 20 人全部降级） |
| 经验复用 | A 的问题 → 记录路线；B 同主题 → prompt 里带上 A 的工具与 pid |
| 延迟 | 扩充 ~10–20s（OpenAlex 限速），只在对应用户那一次发生 |

## API

| 端点 | 说明 |
|---|---|
| `GET /episodes/stats` | 经验库规模 |
| `GET /episodes/recall?q=` | 给定问题召回历史路线（含注入文本） |
| `POST /library/expand` | 手动按主题扩充（写接口） |
| `POST /library/publish` | 发布待复核的扩充作者 |
| `GET /library/expansions` | 扩充历史（谁扩了什么、结果如何） |

## 局限

1. 扩充精度受限于"标题匹配"：做同一疾病但标题不写病名的作者会漏；
2. 稀有病的 OpenAlex 覆盖本身有限（Niemann-Pick 只收到 1 人）；
3. 没有人工复核界面（目前是 `pending` + API 发布）；
4. 经验复用是"提示注入"，没有做"直接复用候选 pid"的强约束；
5. 24 小时同主题只扩一次，热点主题可能不够。
