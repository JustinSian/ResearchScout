# M4 报告：LangGraph Agent（工具 + 引用 + 拒答 + SSE）

## 结构

```
planner（确定性规则） → execute（调工具） → compose（模板作答 + 引用）
```

**为什么规划器不用 LLM**：演示环境没有可靠模型可用，而这五个意图用规则就能判准
（实测 24 题工具选择 100%）。用规则还带来两个好处：每一步可解释、可单测。

## 5 个工具

| 工具 | 作用 | 为什么需要它 |
|---|---|---|
| `find_expert` | 按研究方向找专家 | M2 发现主题查询 BM25 可以，但排序噪声大 |
| `profile` | 画像：作品数/被引/主题/代表作 | 单条实体深挖 |
| `collaborators` | 合作网络（递归 CTE） | **M2 证明检索对这类问题全 0**，必须走图 |
| `works` | 检索论文 | 论文是主要证据载体 |
| `compare` | 对比 2~3 位专家 | 多实体比较，检索做不到 |

## 拒答：又踩了"便宜信号分不开"的坑

第一版 `find_expert` 直接用人物检索，结果乱编主题（`quantum gravity phenology`）也能返回专家。
实测两种便宜信号**都分不开**：

| 信号 | 有答案 | 没答案 |
|---|---|---|
| dense_max（bge-small） | 0.667 ~ 0.795 | 0.594 ~ **0.735** |
| bm25_top | 6.31 ~ 12.67 | 0 ~ **9.81** |

这与医药项目的结论一致：只有 cross-encoder 能判"这条资料到底答不答得上这个问题"。
复用 .10 上已有的 `bge-reranker` int8 ONNX，得到：

| 候选文本构造 | 有答案 | 没答案 |
|---|---|---|
| A：全局检索到的论文（标题+摘要） | **0.858 ~ 0.999** | 0.000 ~ **0.425** |
| B：人物的代表作标题拼接 | 0.003 ~ 0.954 | 0 ~ 0.009 |

A 明显更好：**0.60 这个阈值可以完全分开两组**。所以 `find_expert` 改成
「检索论文 → CE 判相关 → 聚合到作者」，而不是"直接检索人物"。

## 两个真实 bug（都是"中文提问 + 英文语料"造成的）

**① 中文词进了 FTS 的 AND 条件**
`找研究 graph neural network 的专家` 被拆成 `"找研究" AND "graph" AND "neural" …`，
`"找研究"` 在英文语料里永远匹配不到 → 结果为空 → Agent 判定"没资料"而拒答。
修法：FTS 只保留含 ASCII 字母的 token。

**② 中文提问稀释了 CE 分数**
同一个问题，只把英文部分喂给 CE：
`graph neural network` → **0.999**；混在中文句子里 → **0.175**（低于 0.60 门槛 → 误拒）。
修法：加 `latin_query()`，检索与打分只用英文关键词，回答仍用原问题。

这两条如果不修，表现就是"6 条真实方向全被拒答"，而原因完全看不出来。

## 评测（24 题：5 类工具 + 4 类拒答）

| 指标 | 结果 |
|---|---|
| 工具选择准确率 | **100%**（24/24） |
| 拒答正确率 | **100%**（20 题该答的都答、4 题该拒的都拒） |
| 非拒答带引用率 | **100%** |
| 非拒答含结构化数字率 | **100%** |

拒答样例：
```
Q: 找研究 quantum gravity phenology 的专家
→ 知识库里没有找到能支撑这个问题的资料。
  （我尝试的工具：find_expert；如果这是合作关系类问题，请给出具体人名…）
```

## SSE

`GET /chat/stream?q=…` 事件序列：`plan` → `token`×N → `citations` → `done`，
拒答时是 `plan` → `refused` → `done`。

## 接口

```
POST /chat?q=            （GET 也支持，便于 curl）
GET  /chat/stream?q=     SSE
GET  /agent/tools        工具清单 + 拒答阈值
```

## 遗留问题

1. **作者聚合较粗**：一条命中论文的所有作者都会按 CE 分加权，
   于是查 "graph neural network" 时可能把 Jerome Friedman 排上来（他的论文摘要也提到 neural network）。
   改进方向：按"该人命中论文的占比"归一化，而不是求和。
2. **没有 LLM 合成**：回答是模板拼装的，不是自然语言生成。好处是可测，坏处是读起来生硬。
3. **单轮**：没有多轮对话与指代消解（医药项目里做过，这里没搬）。
