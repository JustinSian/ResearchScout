# M48：更正——"跨人混淆只有 67%"是实验 bug，不是判据天花板

## 先认错

m46/m47 的结论是"跨人领域混淆只检出 67%，这是内容判据的天花板"。
**这个结论是错的**，原因是注入器写错了。

### bug 在哪

```python
others = [t for p in pids for t in _real_terms(p, 2)]
dirty_cross = [_corrupt(c, "cross", others[:2]) for c in clean]
```

`others[:2]` 永远是**第一个人的**主题词。于是：

- 对第一个人（pid=527）来说，"跨人注入"注入的是**他自己的词** → 与干净数据完全相同 → **必然漏检**；
- 对第二、三个人，才是真的跨人。

用 3 个人时，大约 1/3 的 domain claim 是"假注入"，正好解释了稳定出现的 67%（2/3 命中率）。

## 修正

按 claim 的 pid 选**别人**的词：

```python
terms_by_pid = {p: _real_terms(p, 2) for p in pids}
def _other_terms(pid):
    return next((t for q, t in terms_by_pid.items() if q != pid and t), ["medieval","poetry"])
```

## 修正后的结果：全部 100%，误报 0%

| 场景 | 干净误报 | 无意义注入 | 跨人注入 | 每 100 条 |
|---|---|---|---|---|
| 远领域（527/503/628） | 0% | 100% | **100%** | 122–174ms |
| 近邻（527 与 628，都是 COVID） | 0% | 100% | **100%** | 132ms |

四类 claim（metric / term / domain / coauthor）在两种注入下都是 100%。

**结论修正**：在当前样本上，**内容级判据（词项区分度）足够识别跨人领域混淆**，
m47 里"必须引入身份级信号"的判断被收回。

## 那 m47 的工作白做了吗？没有

`_specific_terms`（相对强度判据）留下了，因为它解决的是另一个真问题：

| 版本 | 干净误报 | 跨人检出 |
|---|---|---|
| 只看"标题含不含这些词" | 0% | 67%（含假注入） |
| 加"作者排行前 20" | **13%**（误拒钟南山的 asthma） | — |
| 改"相对强度 ≥5 篇且 ≥0.8×均值" | **0%** | 100% |

也就是说：**判据从"含不含"升级成"够不够专属"，才能在不误伤真实主题的前提下拦住错配。**

## 教训（写给下一次的自己）

1. **注入实验的第一条规则：注入必须真的改变被测量**。
   写完之后应该跑一次"注入前后对象是否相同"的自检——我没做；
2. **指标稳定在 2/3 这种"整齐"的分数时，先怀疑构造**。67% 恰好等于 2/3，
   这是"三分之一样本没被真正注入"的典型信号，我当时却去解释它；
3. **负结果也要复核**。m47 花了一轮去解释一个不存在的天花板，
   真正的瓶颈是测试代码，不是检索/校验能力。

## 现状

- `app/ab_verifier.py`：注入映射按 pid 取"别人的词"；预热词表统计（每 100 条 ~120ms）
- `app/subagents.py`：`_specific_terms` 相对强度判据（保留）；共现判据试过后**移除**
  （在修正后的注入下它不带来增益，留代码只会增加复杂度）
- 测试：153 项通过

## 仍然成立的局限

1. 样本仍小（15 条 / 3 人），100% 的置信区间很宽，换成 60 条可能掉；
2. **同名不同人**（两个 "Jun Liu"）没有测——那才是真正需要身份级信号（ORCID/机构）的场景；
3. 注入的是"claim 层"错误，没覆盖"报告文字与 claim 不一致"的生成层错误。
