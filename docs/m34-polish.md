# M34：精修（排序开关、来源可见、图谱可读性）

不新增能力，只修"能用但用起来别扭"的地方。

## 1. 检索页：排序开关

原来筛选后只能看相关度顺序。现在多一个下拉：**按相关度 / 按被引 / 按作品数**。

默认仍是 `relevance`——**筛选不会偷偷改变排序**，这是上一轮定下的原则；
要按影响力排必须显式选。

实测 `q=lung cancer`（BM25，无筛选）：

| 排序 | 前三位 |
|---|---|
| relevance | Minhua Peng（88）· Jolanda Nikolla（52）· Hyuna Sung（135,487） |
| cites | **Hyuna Sung（135,487）** · Minhua Peng（88）· Jolanda Nikolla（52） |
| works | **Jolanda Nikolla（26 篇）** · Minhua Peng（6 篇）· Hyuna Sung（2 篇） |

relevance 把 13.5 万被引的人排在第三，正好证明"没有偷偷按被引排"。

## 2. 国家来源可见

`country_src` 现在一路透传到界面：

- **专家墙卡片**：国家徽章的 `title` 写着来源（现任机构 / 历史任职 / 机构推断）；
- **画像页**：`国家 CN（现任机构）`；
- **检索结果**：同样带来源标注。

为什么值得做：只有 84% 的国家来自"现任机构"，另外 16% 是历史任职推的。
不标注的话，用户会把两者当成同等可信——上一轮（m33）的翻车就是这么来的。

## 3. 图谱可读性

| 问题 | 修法 |
|---|---|
| 放大后标签糊成一片 | 字号按 `11 / k` 反向补偿，屏幕上恒定 11px |
| 缩小后标签消失 | 同上（下限 k=0.4） |
| 缩放范围过大（0.25~5） | 收紧到 **0.4~3** |
| 能把图拖丢 | 平移加边界（±0.9 倍画布×缩放），拖不丢 |
| 标签贴着节点 | 下移量也按缩放补偿 |

## 验收

| 项 | 结果 |
|---|---|
| 排序开关 | 三种排序前三位不同，relevance 不按被引 ✓ |
| country_src | `/people/628`、`/experts`、`/search` 均返回 ✓ |
| 页面控件 | `ssort` / `countryChip` / `clampPan` 均在 ✓ |
| 测试 | 79 项全过 |

## 遗留

1. 排序开关只在检索页，专家墙本来就是按字段排的，不需要；
2. `relevance` 与筛选同时用时，候选池上限 300，极端组合下会不足 10 条；
3. 图谱的标签仍可能重叠（没有做碰撞检测），节点密集时需要放大看。
