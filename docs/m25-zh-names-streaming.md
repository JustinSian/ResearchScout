# M25：中文名 + 真流式（含一个隧道坑）

用户两条反馈：**"大多数还是英文专家名"**、**"SSE 不像流式，也没有 Agent 的语言"**。

## 一、中文名：数据缺，不是显示 bug

OpenAlex 只有拉丁转写（`Kefang Lai`），没有汉字。全库 47,569 人，
`name_zh` 原本只有 11 条（某学术图谱导入 + 手工别名）。

### 做了什么

1. **人工映射 16 人**（只收我能确认的：钟南山、李兰娟、何建行、关伟杰、赖克方、
   冉丕鑫、杨子峰、郑劲平、梁文华、黎毅敏、卢文菊、周玉民、陈荣昌…）；
2. **同名传播**：同一位专家在库里常有两条记录（某学术图谱 + OpenAlex），
   中文名只写在一条上。按同英文名把中文名复制过去，补了 **25 条记录**；
3. **补录接口 + 前端按钮**：画像页没有中文名时显示「补中文名」，
   填完即写库并同步 FTS（`POST /people/{pid}/name-zh`，需 API Key）；
4. 提供 `GET /zh-names/missing` 列出仍缺中文名的高被引专家。

结果：全库有中文名 **41 人**，102 位建档专家里 **15 人**。

### 为什么不做自动音译

"Jun Liu" 可能是刘军 / 刘俊 / 刘珺——音译猜错就是**指错人**。
宁可显示英文，也不写一个错的中文名。

### 真正的解法

从某学术图谱 483 人批量导入（那份数据有 `metadata.name_en` ↔ 中文名的对照），
一次能补几百人。这需要 OpenAlex key 做富化，现在 key 已激活，可以排期。

### 踩的坑

库里存的是 `Wei‐jie Guan`（U+2010 连字符），映射表写的是普通 `-`，
精确匹配直接漏掉。改成**规范化匹配**（统一连字符、忽略大小写/空白）后命中率才上来。

## 二、流式：本地是真流，公网被隧道缓冲了

### 先量了

| 路径 | 首 token | 末 token | 结论 |
|---|---|---|---|
| 本机 127.0.0.1 | **0.04 s** | 1.93 s | 真流式 |
| 公网隧道 | 2.86 s | 2.86 s | **全部一次性到达** |

原因是 Cloudflare quick tunnel 对 SSE 做了缓冲。服务端已经加了反缓冲头
（`no-transform` / `X-Accel-Buffering: no` / `Content-Encoding: identity`），
隧道仍不买账。

### 两手处理

1. **前端兜底**：收到的字符先进 `pending`，定时器按 12 字/35ms 匀速吐出，
   肉眼可见"在写"；积压超过 240 字时自动加速到 40 字/35ms。
   这样无论传输层怎么缓冲，观感都是流式。
2. **服务端真流式**：6 字/25ms 推送，本机直连时是真的逐字。

**诚实说明**：公网看到的"打字效果"是前端补的，不是网络真的在流。
如果换一个不缓冲的反代（或直连），两者就是一致的。

## 三、让它"像 Agent"：叙述层

没有 LLM，但"像 Agent"不等于必须有大模型——关键是**说清楚在做什么、依据是什么**。

`app/narrate.py` 生成三类句子，每条都绑定真实数据：

```
收到。你问的是「介绍一下钟南山」，我会读这位专家的完整档案，而不是只搜关键词。
执行：拉出画像与代表作…
（答案逐字出现）
提醒：本系统没有大模型，回答由确定性规则 + 数据库事实拼装，不会编造。
以上每条结论都能点回证据（4 条引用）。需要我把这些人拉到图谱里看关系吗？
```

- **开场**：按意图定制（对比 / 审稿 / 画像 / 检索）；
- **过程**：每个工具一句话（"逐条核对结论能否回溯…"）；
- **收尾**：提醒局限 + 引用条数 + 下一步建议；
- **拒答**：明确说"资料不足，我不猜——这是拒答，不是失败"。

### 是否算"编造"

不算，但要说清楚：这些句子是**模板**，不是模型生成。
模板绑定的是真实工具结果；不会出现"根据我的分析，该专家在国际上享有盛誉"这种无据评论——
这既是限制，也是这个系统比裸 LLM 更可信的地方。

## 四、还没做的

1. 某学术图谱 483 人批量导入（补中文名最快的路）；
2. 非中文专家的中文译名（外国专家其实不需要）；
3. 换非缓冲反代（或直接暴露端口）让公网也是真流式。
