# M54：LLM Agent 主循环 + 长短期记忆

## 定位变化

项目从"确定性检索服务"升级为 **LLM 在环的 Agent**：模型自己决定查什么、查几次、何时收尾。

| | 旧路径（classic） | 新路径（Agent） |
|---|---|---|
| 规划 | 规则匹配 | 模型 function calling |
| 工具调用 | 一次 | 最多 3 轮 / 4 次，带预算 |
| 记忆 | 仅会话结果集 | 短期摘要 + 长期事实（时间区间） |
| 答案 | 模板拼装 | 模型基于工具结果生成 |
| 降级 | — | 未配置 key / 调用失败 → classic |

## 组成

- `app/agent_llm.py`：工具循环（8 个工具，含 `remember`）、预算、强制收尾、trace；
- `app/session_memory.py`：会话原文（窗口 8）+ 滚动摘要（超 10 轮压缩），存 `chat_ctx.db`；
- `app/user_memory.py` / `memory_recall.py` / `memory_extract.py`：长期记忆读写与注入（只补空位）；
- `rsi.active_policy().plan_prompt` 会追加进 system prompt；`synonyms` 进入检索扩展。

## 实测（14 条 Agent 用例）

```
通过率 93%（13/14）· 工具命中 100% · 记忆使用 21%
平均 1.14 轮 · 单次 $0.0022 · p50 8.8s / p95 16.1s
```

1 条失败是"库外主题该不该拒答"的边界（模型偶尔用常识作答）。已加守卫：
所有工具都无条目时，强制改为"没有找到"；但该用例里 `works` 返回了不相关论文，
守卫不触发——这是判据的边界，记录而不掩盖。

## 成本控制

- `MAX_STEPS=3` / `MAX_CALLS=4` / `BUDGET_USD=0.03`；
- 每轮记录 `steps`（工具、参数、耗时）与 `cost_usd`，可直接进报表；
- 收尾阶段不再给工具，只让模型基于已有证据作答，避免"无限自我检索"。

## 收敛过程

第一版 `MAX_CALLS=7` 时 p50 12.4s、单次 7 次工具调用（大量重复查询）。
收紧到 3 轮 / 4 次并在 system prompt 里明确"同一查询不要重复"后，p50 降到 8.8s、成本从 $0.0031 降到 $0.0022。
